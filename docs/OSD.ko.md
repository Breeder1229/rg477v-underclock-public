# V1.00 FPS/W 표시

Control Center의 Under-clock 제목 오른쪽, **Large 버튼 열 바로 위의 FPS/W** 토글로 좌측 상단 OSD를 켜고 끕니다. 초기값은 OFF이고 토글 상태는 Control Center에 저장합니다. BAT·FPS·FPS/W를 세로 세 줄로 약 1초마다 표시합니다. RG477V 8GB 한 대의 최종 APK에서 실제 ±배터리 전력, 제어된 30·60fps·정지0 FPS와 비율 계산을 확인했습니다. [검증 범위](VERIFICATION.ko.md)을 참고하세요.

## BAT: 부호 있는 배터리 전력 추정

**BAT -8.4 W**는 배터리 방전, **BAT +3.2 W**는 센서가 측정한 배터리 순충전, **BAT 0.0 W**는 유효한 0 전류입니다. BAT는 배터리 잔량%가 아닙니다. 충전 케이블 연결 자체가 +라는 뜻은 아니며, 연결 중에도 배터리가 보조 공급하면 -가 표시됩니다. 센서 부호를 뒤집거나 케이블 상태만으로 부호를 만들지 않습니다.

BAT는 미보정 배터리 전류·전압에 따른 **순배터리 전력 추정치**이며 정밀 계측값·충전기 입력 전력·CPU/GPU 단독 소비전력이 아닙니다. 외부 전원이 없을 때 음수값의 크기는 화면·팬·무선 통신 등을 포함한 기기 전체 배터리 부하의 추정치입니다. **외부 전원 연결 중에는 순충전/방전만 보여주므로 기기 전체 소비전력으로 해석할 수 없습니다.** 평균·누적 Wh·차트·기록은 만들지 않습니다.

Android BatteryManager CURRENT_NOW를 약 1초마다 읽습니다. 단위는 **µA**, 음수는 방전이고 양수는 배터리로 들어오는 순충전입니다. 전압은 ACTION_BATTERY_CHANGED의 마지막 유효 **mV** 값입니다. 전압 방송은 시스템·센서의 주기를 따르므로 매초 새 전압이 전달된다는 뜻은 아닙니다. 계산식은 **signed W = 전류(µA) × 전압(mV) ÷ 1,000,000,000**이며 sysfs voltage_now의 µV를 섞지 않습니다.

센서 미지원이면 **BAT · 센서 없음**, 잘못된 값이면 **BAT · 센서 확인**, 아직 배터리 상태를 확인하지 못하면 **BAT · 대기**로 표시합니다. 전류 크기 10,000,000µA 이하, 전압 2,500~5,000mV만 허용하며 미지원 sentinel·NaN·무한대·범위 오류를 W로 표시하지 않습니다. 이 범위 검사는 센서 정확도 보정이 아닙니다. 충전 중 +값을 센서에서 얻을 수 없으면 숫자를 만들어 내지 않습니다.

## FPS와 FPS/W

표시 예:

```text
BAT -8.4 W
FPS 60.0
FPS/W 7.1
```

FPS는 **현재 전면 앱의 단일 SurfaceView가 화면에 제시한 프레임**을 셉니다. 화면 주사율이나 Control Center 자체 애니메이션 FPS를 대신 표시하지 않습니다. 에뮬레이터 내부 게임의 논리 FPS와 구분할 수는 없습니다.

기존 시스템 UID1000 권한으로 SurfaceFlinger에 read-only Binder dumpAsync를 보내 --list와 해당 foreground component의 유일한 SurfaceView(BLAST) --latency를 읽습니다. shell·루트·Shizuku를 실행하지 않으며 전역 timestats를 켜거나 지우지 않습니다. 실제 present 시각인 두 번째 열을 System.nanoTime과 같은 단조 시각 기준으로 비교합니다. 연속 두 관측 사이의 새 present 수를 경과 시간으로 나눕니다. 시작·앱 전환·화면 재개 때는 먼저 기준을 잡으며, 프레임이 실제로 정지하면 이전 FPS를 재사용하지 않고 0을 표시합니다.

FPS/W는 **외부 전원 없이 방전 중일 때, 같은 갱신의 FPS ÷ 방전 전력의 크기(−signed W)**입니다. 음수 BAT를 그대로 분모에 넣어 음수 효율을 만들지 않습니다. CPU·GPU만의 효율이나 보정된 정밀 전성비가 아닙니다. FPS는 약 1초 관측 구간이고 전력은 그 갱신의 순간 전류와 최신 전압을 사용하므로, 두 센서가 하드웨어 수준에서 완전히 동기화된 계측은 아닙니다.

지원하는 SurfaceView가 없거나 여러 개라 대상이 모호하면 FPS는 **—**입니다. 127개 프레임 기록에서 이전 기준이 유실됐거나, 관측 간격이 2초를 넘거나, 타임스탬프가 잘못됐을 때도 —로 표시합니다. 주사율·최근 최대값·다른 앱의 FPS로 보정하지 않습니다. 전력 또는 FPS가 유효하지 않거나 외부 전원이 연결됐거나, signed W가 양수 또는 0이면 FPS/W는 **—**입니다. 연결 중 BAT가 음수여도 순배터리 전력을 전체 기기 소비로 볼 수 없어 FPS/W는 계산하지 않습니다. 앱·게임별 지원을 보장하지 않습니다.

## 수명과 복구

표시는 기존 native Control Center 프로세스에서 동작합니다. 별도 Under-clock 앱을 닫거나 강제 종료해도 유지됩니다. native 프로세스가 실제로 교체된 뒤 ON 상태와 창 한 개가 복원됨을 확인했습니다. 기존 v0.5.1의 기기 전체 재부팅은 시험하지 않았습니다. V1.00에서 새로 수행한 검사는 검증 요약을 참고하세요. 루트·Shizuku를 사용하지 않습니다. 작은 반투명 창은 터치와 입력 포커스를 받지 않으며, 화면을 끄면 창과 반복 샘플을 멈춥니다.

토글 OFF는 샘플 callback·창·배터리/화면 receiver·복구 observer를 정리합니다. 순정 복구는 별도 표시 중지 요청을 기록하고 가능하면 정리 응답을 확인한 뒤 기존 Default·순정 교체 절차를 진행합니다. 이미 OFF이거나 기존 버전 native인 경우 표시 때문에 복구를 막지 않습니다. 죽은 프로세스의 응답이 없더라도 순정 APK 교체가 해당 프로세스와 창을 제거하며, 기록된 복구 fence는 중간 재시작 시 표시의 재활성화를 차단합니다. 복구 후 명시 재설치를 해도 표시는 OFF로 시작하며 다시 켜야 합니다.

이 기능은 기존 프로필·클럭·팬·추가 열제어 정책을 바꾸지 않습니다.

API 기준: [Android BatteryManager](https://developer.android.com/reference/android/os/BatteryManager), [WindowManager.LayoutParams](https://developer.android.com/reference/android/view/WindowManager.LayoutParams).

**Dimensity 8300 언더클럭을 위해 개발했으며, 실기 구동은 RG477V 8GB에서만 확인했습니다. RG557·RG477M·RG477V 12GB에서는 확인하지 않았습니다.** 같은 칩셋이나 모델 이름만으로 호환을 보장하지 않으며, 명시한 정확한 펌웨어·Control Center 검사는 그대로 적용합니다.
